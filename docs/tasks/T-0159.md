## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`linkRequests.approve`** — `POST /api/v1/staff/link-requests/{requestId}/approve` · สิทธิ์ `staff` roles `OF`

Response: `LinkRequestItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `customer_link_request:pending→approved`
Audit: `customer.merge_link_approve`
Notify: `customer.link_approved`
ผลที่ต้องเกิด:
- ย้าย line_identity ไปผูก owner_profile ของ candidate
- ย้ายน้อง/ใบจองที่สร้างจาก profile ใหม่ (ถ้ามี) ไปยังลูกค้าเดิม
- ลบ owner_profile ใหม่ที่ว่างแล้ว

## Test cases ที่ต้องมี (integration, PGlite)

**linkRequests.approve** (POST `/api/v1/staff/link-requests/{requestId}/approve`)
  - happy path: response ตรง schema `LinkRequestsApproveResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์

  - audit_log action `customer.merge_link_approve` ถูกเขียนใน transaction เดียวกัน
  - notification outbox: `customer.link_approved` (ตรวจ dedupe_key)
  - effect: ย้าย line_identity ไปผูก owner_profile ของ candidate
  - effect: ย้ายน้อง/ใบจองที่สร้างจาก profile ใหม่ (ถ้ามี) ไปยังลูกค้าเดิม
