## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`bills.list`** — `GET /api/v1/staff/bills` · สิทธิ์ `staff` roles `OF`

Query:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `status` | enum:bill_status |  | bill.status |  |
| `date` | date |  |  | closed_at หรือ opened_at ตามสถานะ |
| `cursor` | string |  |  |  |

Response: `Paged<BillListItem>` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

**`bills.get`** — `GET /api/v1/staff/bills/{billId}` · สิทธิ์ `staff` roles `OF`

Response: `BillDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

**`bills.updateLine`** — `PATCH /api/v1/staff/bill-lines/{lineId}` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `lineDiscountSatang` | int |  | bill_line.line_discount_satang | ≤ qty × unit |
| `lineDiscountReason` | string |  | bill_line.line_discount_reason | บังคับเมื่อ > 0 |
| `performerId` | uuid |  | bill_line.performer_id |  |
| `quantity` | int |  | bill_line.quantity | quick_item เท่านั้น |

Response: `BillDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Errors: `BILL_NOT_OPEN`, `LINE_DISCOUNT_TOO_LARGE`, `DISCOUNT_LIMIT_EXCEEDED`, `REASON_REQUIRED`
Audit: `bill.discount`
ผลที่ต้องเกิด:
- bill_line เป็น append-only ใน ORM? ไม่ — แก้ได้ขณะบิล open โดย delete+insert ใน transaction

## Test cases ที่ต้องมี (integration, PGlite)

**bills.list** (GET `/api/v1/staff/bills`)
  - happy path: response ตรง schema `BillsListResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
**bills.get** (GET `/api/v1/staff/bills/{billId}`)
  - happy path: response ตรง schema `BillsGetResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
**bills.updateLine** (PATCH `/api/v1/staff/bill-lines/{lineId}`)
  - happy path: response ตรง schema `BillsUpdateLineResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - error `BILL_NOT_OPEN`
  - error `LINE_DISCOUNT_TOO_LARGE`
  - error `DISCOUNT_LIMIT_EXCEEDED`
  - error `REASON_REQUIRED`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - audit_log action `bill.discount` ถูกเขียนใน transaction เดียวกัน
  - effect: bill_line เป็น append-only ใน ORM? ไม่ — แก้ได้ขณะบิล open โดย delete+insert ใน transaction
