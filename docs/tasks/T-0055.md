## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`vaccinations.create`** — `POST /api/v1/staff/pets/{petId}/vaccinations` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `vaccineCode` | string | ✓ | pet_vaccination.vaccine_code | ต้องตรง species ของน้อง |
| `administeredOn` | date |  | pet_vaccination.administered_on | ≤ วันนี้ |
| `expiresOn` | date |  | pet_vaccination.expires_on | ไม่ส่ง = administeredOn + default_validity_months |
| `proofFileId` | uuid |  | pet_vaccination.proof_file_id | kind vaccine_proof |

Response: `VaccinationItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
ผลที่ต้องเกิด:
- status verified, source shop, verified_org_id/by/at

**`vaccinations.verify`** — `POST /api/v1/staff/vaccinations/{vaccinationId}/verify` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `expiresOn` | date |  | pet_vaccination.expires_on | แก้ได้ก่อนยืนยัน |

Response: `VaccinationItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `pet_vaccination:pending_review→verified`

**`vaccinations.reject`** — `POST /api/v1/staff/vaccinations/{vaccinationId}/reject` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `reason` | string | ✓ | pet_vaccination.reject_reason | ≥ 3 |

Response: `VaccinationItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `pet_vaccination:pending_review→rejected`
Notify: `customer.vaccine_rejected`

## Test cases ที่ต้องมี (integration, PGlite)

  - happy path: response ตรง schema `VaccinationsCreateResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
