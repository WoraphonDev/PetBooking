## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`auth.staffLogin`** — `POST /api/v1/auth/staff/login` · สิทธิ์ `public`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `email` | string | ✓ | staff_user.email | อีเมล, trim + lowercase |
| `password` | string | ✓ |  | 1–128 ตัว |

Response: `StaffMe` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Errors: `INVALID_CREDENTIALS`, `ACCOUNT_LOCKED`, `RATE_LIMITED`
ผลที่ต้องเกิด:
- สร้าง session (subject staff, อายุ 30 วัน sliding) ตั้ง cookie `sid` httpOnly Secure SameSite=Lax
- อัปเดต staff_user.failed_login_count/locked_until/last_login_at ตาม R-24
- rate limit 10 ครั้ง/นาที/IP

## Test cases ที่ต้องมี (integration, PGlite)

**auth.staffLogin** (POST `/api/v1/auth/staff/login`)
  - happy path: response ตรง schema `AuthStaffLoginResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - error `INVALID_CREDENTIALS`
  - error `ACCOUNT_LOCKED`
  - error `RATE_LIMITED`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - effect: สร้าง session (subject staff, อายุ 30 วัน sliding) ตั้ง cookie `sid` httpOnly Secure SameSite=Lax
  - effect: อัปเดต staff_user.failed_login_count/locked_until/last_login_at ตาม R-24
  - effect: rate limit 10 ครั้ง/นาที/IP
