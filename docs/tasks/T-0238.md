## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`reportCards.submit`** — `POST /api/v1/staff/report-cards/{reportCardId}/submit` · สิทธิ์ `staff` roles `OFS`

Response: `ReportCardDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `report_card:draft→pending_review|sent`
Notify: `customer.report_card`
ผลที่ต้องเกิด:
- policy report_card_requires_review → pending_review (แจ้งหน้าร้าน) ไม่งั้น sent
- sent: แนบรูป after ≤ 4 รูป (ถ้า photo_consent ≠ denied), ลิงก์หน้า report card ใน LIFF

## Test cases ที่ต้องมี (integration, PGlite)

**reportCards.submit** (POST `/api/v1/staff/report-cards/{reportCardId}/submit`)
  - happy path: response ตรง schema `ReportCardsSubmitResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `report_card:draft→pending_review|sent` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - notification outbox: `customer.report_card` (ตรวจ dedupe_key)
  - effect: policy report_card_requires_review → pending_review (แจ้งหน้าร้าน) ไม่งั้น sent
  - effect: sent: แนบรูป after ≤ 4 รูป (ถ้า photo_consent ≠ denied), ลิงก์หน้า report card ใน LIFF
