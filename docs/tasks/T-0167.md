## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`slips.verify`** — `POST /api/v1/staff/slips/{slipId}/verify` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `amountSatang` | int | ✓ | payment.amount_satang | ยอดที่เข้าจริง > 0 |
| `confirmDuplicate` | bool |  |  | ต้อง true ถ้าสลิปซ้ำ |
| `approveBooking` | bool |  |  | true = อนุมัติใบจองต่อในคำสั่งเดียว (ถ้าต้องอนุมัติ) |

Response: `SlipItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Errors: `DUPLICATE_SLIP_CONFIRM_REQUIRED`, `STATUS_NOT_ALLOWED`
State: `payment_slip:submitted→verified; booking:deposit_review→confirmed|awaiting_approval`
Audit: `slip.verify`
Notify: `customer.deposit_confirmed`
ผลที่ต้องเกิด:
- insert payment (method promptpay, slip_id) → booking.deposit_verified_satang += amount; deposit_status verified
- สลิปของบิล (bill_id) → payment ของบิลแทน
- ยอดน้อยกว่าที่ต้องจ่าย → deposit_status คง submitted? ไม่: verified บางส่วน + แสดงยอดค้างในใบจอง

## Test cases ที่ต้องมี (integration, PGlite)

**slips.verify** (POST `/api/v1/staff/slips/{slipId}/verify`)
  - happy path: response ตรง schema `SlipsVerifyResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - error `DUPLICATE_SLIP_CONFIRM_REQUIRED`
  - error `STATUS_NOT_ALLOWED`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `payment_slip:submitted→verified; booking:deposit_review→confirmed|awaiting_approval` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - audit_log action `slip.verify` ถูกเขียนใน transaction เดียวกัน
  - notification outbox: `customer.deposit_confirmed` (ตรวจ dedupe_key)
  - effect: insert payment (method promptpay, slip_id) → booking.deposit_verified_satang += amount; deposit_status verified
  - effect: สลิปของบิล (bill_id) → payment ของบิลแทน
  - effect: ยอดน้อยกว่าที่ต้องจ่าย → deposit_status คง submitted? ไม่: verified บางส่วน + แสดงยอดค้างในใบจอง
