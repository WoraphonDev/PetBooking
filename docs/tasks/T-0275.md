## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`stays.checkIn`** — `POST /api/v1/staff/stays/{stayId}/check-in` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `weightGrams` | int |  | stay.weight_grams_in |  |
| `vaccineOverrideReason` | string |  | stay.vaccine_override_reason | บังคับเมื่อ R-11 ไม่ผ่าน |

Response: `StayDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Errors: `INTAKE_INCOMPLETE`, `CONSENT_REQUIRED`, `VACCINE_REQUIRED`, `STATUS_NOT_ALLOWED`
State: `stay:reserved→checked_in`
Audit: `stay.vaccine_override (เมื่อ override)`
Notify: `customer.stay_checked_in`
ผลที่ต้องเกิด:
- ต้องมี intake completed + agreement
- checked_in_at = now; สร้าง care_task ตาม R-26
- ทำได้ตั้งแต่วัน check_in_date (ก่อนหน้านั้น STATUS_NOT_ALLOWED)

## Test cases ที่ต้องมี (integration, PGlite)

**stays.checkIn** (POST `/api/v1/staff/stays/{stayId}/check-in`)
  - happy path: response ตรง schema `StaysCheckInResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - error `INTAKE_INCOMPLETE`
  - error `CONSENT_REQUIRED`
  - error `VACCINE_REQUIRED`
  - error `STATUS_NOT_ALLOWED`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `stay:reserved→checked_in` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - audit_log action `stay.vaccine_override` ถูกเขียนใน transaction เดียวกัน
  - notification outbox: `customer.stay_checked_in` (ตรวจ dedupe_key)
  - effect: ต้องมี intake completed + agreement
  - effect: checked_in_at = now; สร้าง care_task ตาม R-26
  - effect: ทำได้ตั้งแต่วัน check_in_date (ก่อนหน้านั้น STATUS_NOT_ALLOWED)
