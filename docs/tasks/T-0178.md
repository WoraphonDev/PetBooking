## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`liff.uploadSlip`** — `POST /api/v1/liff/{branchSlug}/bookings/{bookingId}/slips` · สิทธิ์ `customer`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `fileId` | uuid | ✓ | payment_slip.file_id | kind slip |
| `qrPayload` | string |  | payment_slip.qr_payload | ข้อความจาก QR บนสลิป (client decode) |

Response: `MyBookingDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Errors: `HOLD_EXPIRED`, `STATUS_NOT_ALLOWED`
State: `booking:awaiting_deposit→deposit_review`
Notify: `staff.slip_submitted`
ผลที่ต้องเกิด:
- parse R-05 → trans_ref, duplicate_of_slip_id
- deposit_status submitted; ล้าง hold_expires_at

**`liff.ics`** — `GET /api/v1/liff/{branchSlug}/bookings/{bookingId}/calendar.ics` · สิทธิ์ `customer`

Response: `text/calendar`
ผลที่ต้องเกิด:
- 1 VEVENT ต่อนัด/การพัก, LOCATION = ที่อยู่ร้าน, URL = Google Maps

**`liff.payPage`** — `GET /api/v1/liff/{branchSlug}/pay/{billId}` · สิทธิ์ `customer`

Response: `PaymentInstruction` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

## Test cases ที่ต้องมี (integration, PGlite)

**liff.uploadSlip** (POST `/api/v1/liff/{branchSlug}/bookings/{bookingId}/slips`)
  - happy path: response ตรง schema `LiffUploadSlipResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์

  - error `STATUS_NOT_ALLOWED`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`

  - state: `booking:awaiting_deposit→deposit_review` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
