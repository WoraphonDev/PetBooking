## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`customers.list`** — `GET /api/v1/staff/customers` · สิทธิ์ `staff` roles `OF`

Query:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `q` | string |  |  |  |
| `sort` | enum |  |  | last_visit_desc \| name_asc \| created_desc |
| `cursor` | string |  |  |  |
| `limit` | int |  |  | 1–200 |

Response: `Paged<CustomerListItem>` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

**`customers.create`** — `POST /api/v1/staff/customers` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `firstName` | string | ✓ | owner_profile.first_name | 1–60 |
| `lastName` | string |  | owner_profile.last_name | ≤ 60 |
| `nickname` | string |  | owner_profile.nickname | ≤ 30 |
| `phone` | string |  | owner_profile.phone_e164 | R-22 (แนะนำให้มี) |
| `email` | string |  | owner_profile.email |  |
| `sourceChannel` | enum:booking_channel |  | customer.source_channel | default walk_in |
| `referralNote` | string |  | customer.referral_note |  |
| `internalNote` | string |  | customer.internal_note | ≤ 2000 |
| `photoConsent` | enum:photo_consent |  | customer.photo_consent | default unknown |

Response: `CustomerDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Errors: `INVALID_PHONE`
ผลที่ต้องเกิด:
- สร้าง owner_profile (created_in_org_id = org) + customer ใน transaction
- เบอร์ซ้ำกับลูกค้าเดิมในร้าน → ไม่ error แต่ตอบ warnings[] {duplicateCustomerIds}

**`customers.get`** — `GET /api/v1/staff/customers/{customerId}` · สิทธิ์ `staff` roles `OFS`

Response: `CustomerDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
ผลที่ต้องเกิด:
- role staff: ไม่เห็น phone, email, address, internalNote, creditBalance (ตัดออกจาก response)

## Test cases ที่ต้องมี (integration, PGlite)

  - happy path: response ตรง schema `CustomersListResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์

  - role staff → `FORBIDDEN`

  - effect: สร้าง owner_profile (created_in_org_id = org) + customer ใน transaction
  - effect: เบอร์ซ้ำกับลูกค้าเดิมในร้าน → ไม่ error แต่ตอบ warnings[] {duplicateCustomerIds}
