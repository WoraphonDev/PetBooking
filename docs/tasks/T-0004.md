## Steps

1. context.ts: `RequestContext` ตาม 01 §4 + `makeSystemCtx(orgId, now)`
2. errors.ts: `class AppError(code: ErrorCode, details?)`; `mapPgError(e)`: 23P01 + constraint `groom_appt_*` → SLOT_TAKEN, `stay_room_no_overlap` → ROOM_TAKEN, `stay_pet_no_overlap` → PET_ALREADY_BOOKED; 23505 → ตามชื่อ unique index (`*_slug_uq` → SLUG_TAKEN, `staff_user_email_uq` → EMAIL_TAKEN, `*_code_uq` → CODE_TAKEN); 23503 on delete → IN_USE; อื่น ๆ → INTERNAL
3. db.ts: `getDb()` (singleton จาก DATABASE_URL) + `withTx(ctx, fn)` + ทางฉีด db สำหรับเทสต์
4. repo/tenant.ts: `tenantDb(ctx, tx)` คืน helper `select/insert/update` ที่บังคับ `organization_id = ctx.orgId` สำหรับตารางที่มีคอลัมน์นี้ (insert เติมให้อัตโนมัติ, update/select เติม where) — ตารางที่ไม่มี organization_id ต้องเข้าถึงผ่าน join ที่ตรวจ org
5. test/helpers: `setupTestDb()` (createTestDb + seedBase), `staffCtx(base, role)`, `customerCtx`, `otherOrg()` (สร้าง org ที่ 2)
6. test/core: tenantDb ไม่คืนแถวของ org อื่น; mapPgError ครบทุกกรณี
