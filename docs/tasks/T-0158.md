## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`linkRequests.list`** — `GET /api/v1/staff/link-requests` · สิทธิ์ `staff` roles `OF`

Response: `LinkRequestItem[]` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

**`linkRequests.reject`** — `POST /api/v1/staff/link-requests/{requestId}/reject` · สิทธิ์ `staff` roles `OF`

Response: `LinkRequestItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `customer_link_request:pending→rejected`
ผลที่ต้องเกิด:
- profile ใหม่กลายเป็นลูกค้าใหม่ของร้าน

## Test cases ที่ต้องมี (integration, PGlite)

**linkRequests.list** (GET `/api/v1/staff/link-requests`)
  - happy path: response ตรง schema `LinkRequestsListResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
**linkRequests.reject** (POST `/api/v1/staff/link-requests/{requestId}/reject`)
  - happy path: response ตรง schema `LinkRequestsRejectResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `customer_link_request:pending→rejected` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - effect: profile ใหม่กลายเป็นลูกค้าใหม่ของร้าน
