## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`groom.notifyPickup`** — `POST /api/v1/staff/groom-appointments/{appointmentId}/notify-pickup` · สิทธิ์ `staff` roles `OF`

Response: `AppointmentCard` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Notify: `customer.ready_for_pickup`
ผลที่ต้องเกิด:
- ถ้ามี report card sent พร้อมกัน → รวมเป็นข้อความเดียว (R-18 งบข้อความ)

**`groom.pickUp`** — `POST /api/v1/staff/groom-appointments/{appointmentId}/pick-up` · สิทธิ์ `staff` roles `OF`

Response: `AppointmentCard` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `groom_appointment:done→picked_up`
ผลที่ต้องเกิด:
- picked_up_at = now; pet_shop_profile.last_groomed_at = done_at
- ตั้ง job next_groom_reminder ตาม R-17
- บิลยังไม่ปิด → แสดงใน todo.pickupsWithoutBill

## Test cases ที่ต้องมี (integration, PGlite)

**groom.notifyPickup** (POST `/api/v1/staff/groom-appointments/{appointmentId}/notify-pickup`)
  - happy path: response ตรง schema `GroomNotifyPickupResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - notification outbox: `customer.ready_for_pickup` (ตรวจ dedupe_key)
  - effect: ถ้ามี report card sent พร้อมกัน → รวมเป็นข้อความเดียว (R-18 งบข้อความ)
**groom.pickUp** (POST `/api/v1/staff/groom-appointments/{appointmentId}/pick-up`)
  - happy path: response ตรง schema `GroomPickUpResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `groom_appointment:done→picked_up` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - effect: picked_up_at = now; pet_shop_profile.last_groomed_at = done_at
  - effect: ตั้ง job next_groom_reminder ตาม R-17
  - effect: บิลยังไม่ปิด → แสดงใน todo.pickupsWithoutBill
