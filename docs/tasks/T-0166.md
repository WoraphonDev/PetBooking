## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`slips.list`** — `GET /api/v1/staff/slips` · สิทธิ์ `staff` roles `OF`

Query:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `status` | enum:slip_status |  | payment_slip.status | default submitted |

Response: `SlipItem[]` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

**`slips.reject`** — `POST /api/v1/staff/slips/{slipId}/reject` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `reason` | string | ✓ | payment_slip.reject_reason | ≥ 3 ลูกค้าเห็น |

Response: `SlipItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `payment_slip:submitted→rejected; booking:deposit_review→awaiting_deposit|expired`
Audit: `slip.reject`
Notify: `customer.slip_rejected`

## Test cases ที่ต้องมี (integration, PGlite)

**slips.list** (GET `/api/v1/staff/slips`)
  - happy path: response ตรง schema `SlipsListResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
**slips.reject** (POST `/api/v1/staff/slips/{slipId}/reject`)
  - happy path: response ตรง schema `SlipsRejectResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `payment_slip:submitted→rejected; booking:deposit_review→awaiting_deposit|expired` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - audit_log action `slip.reject` ถูกเขียนใน transaction เดียวกัน
  - notification outbox: `customer.slip_rejected` (ตรวจ dedupe_key)
