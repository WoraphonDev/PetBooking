## Test cases ที่ต้องมี (integration, PGlite)

**stays.noShow** (POST `/api/v1/staff/stays/{stayId}/no-show`)
  - happy path: response ตรง schema `StaysNoShowResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `stay:reserved→no_show` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - audit_log action `booking.no_show` ถูกเขียนใน transaction เดียวกัน
  - effect: ทำได้หลัง 23:59 ของ check_in_date หรือกดเองพร้อมยืนยัน
