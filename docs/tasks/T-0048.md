## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`staffUsers.list`** — `GET /api/v1/staff/staff-users` · สิทธิ์ `staff` roles `OFS`

Response: `StaffUserItem[]` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
ผลที่ต้องเกิด:
- role staff เห็นเฉพาะ id, displayName, isGroomer, photoUrl

**`staffUsers.invite`** — `POST /api/v1/staff/staff-users/invite` · สิทธิ์ `staff` roles `O`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `displayName` | string | ✓ | staff_user.display_name | 1–40 |
| `email` | string |  | staff_user.email | อีเมล; ไม่ใส่ = เชิญผ่านลิงก์ LINE |
| `role` | enum:staff_role | ✓ | staff_user.role |  |
| `isGroomer` | bool | ✓ | staff_user.is_groomer |  |

Response: `object {staffUser: StaffUserItem, inviteUrl: string}`
Errors: `EMAIL_TAKEN`
Audit: `staff.invite`
Notify: `staff.invite`
ผลที่ต้องเกิด:
- สร้าง staff_user status invited + staff_invite (7 วัน)
- มีอีเมล → ส่งอีเมล; คืน inviteUrl ให้ส่งทาง LINE เองได้

**`staffUsers.update`** — `PATCH /api/v1/staff/staff-users/{staffUserId}` · สิทธิ์ `staff` roles `O`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `displayName` | string |  | staff_user.display_name |  |
| `phone` | string |  | staff_user.phone | R-22 |
| `role` | enum:staff_role |  | staff_user.role |  |
| `isGroomer` | bool |  | staff_user.is_groomer |  |
| `sortOrder` | int |  | staff_user.sort_order |  |
| `photoFileId` | uuid |  | staff_user.photo_file_id |  |
| `status` | enum:staff_status |  | staff_user.status | active ↔ disabled เท่านั้น |

Response: `StaffUserItem` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Errors: `LAST_OWNER`
State: `staff_user:active↔disabled`
Audit: `staff.role_change`
ผลที่ต้องเกิด:
- disabled → ลบ session ทั้งหมดของคนนั้น; นัดอนาคตของช่างที่ถูกปิดยังอยู่ — ตอบ warnings[]

## Test cases ที่ต้องมี (integration, PGlite)

**staffUsers.list** (GET `/api/v1/staff/staff-users`)
  - happy path: response ตรง schema `StaffUsersListResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - effect: role staff เห็นเฉพาะ id, displayName, isGroomer, photoUrl
**staffUsers.invite** (POST `/api/v1/staff/staff-users/invite`)
  - happy path: response ตรง schema `StaffUsersInviteResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - error `EMAIL_TAKEN`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role front_desk/staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - audit_log action `staff.invite` ถูกเขียนใน transaction เดียวกัน
  - notification outbox: `staff.invite` (ตรวจ dedupe_key)
  - effect: สร้าง staff_user status invited + staff_invite (7 วัน)
  - effect: มีอีเมล → ส่งอีเมล; คืน inviteUrl ให้ส่งทาง LINE เองได้
**staffUsers.update** (PATCH `/api/v1/staff/staff-users/{staffUserId}`)
  - happy path: response ตรง schema `StaffUsersUpdateResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - error `LAST_OWNER`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role front_desk/staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `staff_user:active↔disabled` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - audit_log action `staff.role_change` ถูกเขียนใน transaction เดียวกัน
  - effect: disabled → ลบ session ทั้งหมดของคนนั้น; นัดอนาคตของช่างที่ถูกปิดยังอยู่ — ตอบ warnings[]
