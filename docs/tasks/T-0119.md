## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`groom.start`** — `POST /api/v1/staff/groom-appointments/{appointmentId}/start` · สิทธิ์ `staff` roles `OFS`

Response: `AppointmentCard` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `groom_appointment:checked_in→in_progress`
ผลที่ต้องเกิด:
- role staff ทำได้เฉพาะนัดของตัวเอง
- started_at = now

**`groom.finish`** — `POST /api/v1/staff/groom-appointments/{appointmentId}/finish` · สิทธิ์ `staff` roles `OFS`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `staffNote` | string |  | groom_appointment.staff_note | ≤ 1000 โน้ตถึงร้าน |

Response: `AppointmentCard` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `groom_appointment:in_progress→done`
Notify: `staff.groom_done`
ผลที่ต้องเกิด:
- done_at = now; สร้าง report_card draft (ถ้ายังไม่มี) ให้ช่างกรอก
- แจ้งหน้าร้าน (web push) ว่าน้องเสร็จ

**`groom.cancel`** — `POST /api/v1/staff/groom-appointments/{appointmentId}/cancel` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `reason` | string | ✓ | booking_event.reason | ≥ 3 |

Response: `BookingDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `groom_appointment:scheduled|checked_in→cancelled`
ผลที่ต้องเกิด:
- เป็น child สุดท้ายที่ active → ใช้ flow bookings.cancel แทน (STATUS_NOT_ALLOWED พร้อม hint)
- ลด booking.estimated_total_satang

## Test cases ที่ต้องมี (integration, PGlite)

**groom.start** (POST `/api/v1/staff/groom-appointments/{appointmentId}/start`)
  - happy path: response ตรง schema `GroomStartResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `groom_appointment:checked_in→in_progress` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - effect: role staff ทำได้เฉพาะนัดของตัวเอง
  - effect: started_at = now
**groom.finish** (POST `/api/v1/staff/groom-appointments/{appointmentId}/finish`)
  - happy path: response ตรง schema `GroomFinishResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `groom_appointment:in_progress→done` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - notification outbox: `staff.groom_done` (ตรวจ dedupe_key)
  - effect: done_at = now; สร้าง report_card draft (ถ้ายังไม่มี) ให้ช่างกรอก
  - effect: แจ้งหน้าร้าน (web push) ว่าน้องเสร็จ
**groom.cancel** (POST `/api/v1/staff/groom-appointments/{appointmentId}/cancel`)
  - happy path: response ตรง schema `GroomCancelResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - state: `groom_appointment:scheduled|checked_in→cancelled` + insert booking_event (ถ้าเป็น booking/child) + สถานะต้นทางผิด → `INVALID_TRANSITION`
  - effect: เป็น child สุดท้ายที่ active → ใช้ flow bookings.cancel แทน (STATUS_NOT_ALLOWED พร้อม hint)
  - effect: ลด booking.estimated_total_satang
