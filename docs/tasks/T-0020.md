## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`auth.staffLogout`** — `POST /api/v1/auth/staff/logout` · สิทธิ์ `staff` roles `OFS`

Response: `204`
ผลที่ต้องเกิด:
- ลบ session ปัจจุบัน + ล้าง cookie

**`auth.me`** — `GET /api/v1/auth/staff/me` · สิทธิ์ `staff` roles `OFS`

Response: `StaffMe` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

**`auth.resetRequest`** — `POST /api/v1/auth/staff/password-reset/request` · สิทธิ์ `public`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `email` | string | ✓ | staff_user.email | อีเมล |

Response: `204`
Errors: `RATE_LIMITED`
Notify: `staff.password_reset`
ผลที่ต้องเกิด:
- ตอบ 204 เสมอ (ไม่บอกว่ามีอีเมลไหม)
- มีจริง → สร้าง password_reset (30 นาที) ส่งอีเมลลิงก์

## Test cases ที่ต้องมี (integration, PGlite)

**auth.staffLogout** (POST `/api/v1/auth/staff/logout`)
  - happy path: response ตรง schema `AuthStaffLogoutResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - effect: ลบ session ปัจจุบัน + ล้าง cookie
**auth.me** (GET `/api/v1/auth/staff/me`)
  - happy path: response ตรง schema `AuthMeResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
**auth.resetRequest** (POST `/api/v1/auth/staff/password-reset/request`)
  - happy path: response ตรง schema `AuthResetRequestResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - error `RATE_LIMITED`
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - notification outbox: `staff.password_reset` (ตรวจ dedupe_key)
  - effect: ตอบ 204 เสมอ (ไม่บอกว่ามีอีเมลไหม)
  - effect: มีจริง → สร้าง password_reset (30 นาที) ส่งอีเมลลิงก์
