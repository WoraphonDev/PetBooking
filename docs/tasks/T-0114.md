## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`bookings.cancel`** — `POST /api/v1/staff/bookings/{bookingId}/cancel` · สิทธิ์ `staff` roles `OF`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `kind` | enum | ✓ |  | customer_cancel \| shop_cancel |
| `reason` | string | ✓ | booking.cancel_reason | ≥ 3 |
| `customerChoice` | enum |  |  | refund \| credit |

Response: `BookingDetail` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
State: `booking:*→cancelled`
Audit: `booking.cancel`
Notify: `customer.booking_cancelled`
ผลที่ต้องเกิด:
- children ทั้งหมด → cancelled
- เงินตาม R-07 (credit_ledger / refund pending / forfeited)
- late → customer.late_cancel_count_12m + 1 แล้ว R-09
- ยกเลิก scheduled_job ที่ dedupe_key อ้างใบจองนี้

## Test cases ที่ต้องมี (integration, PGlite)

**bookings.cancel** (POST `/api/v1/staff/bookings/{bookingId}/cancel`)
  - happy path: response ตรง schema `BookingsCancelResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role staff → `FORBIDDEN`

  - audit_log action `booking.cancel` ถูกเขียนใน transaction เดียวกัน
  - notification outbox: `customer.booking_cancelled` (ตรวจ dedupe_key)
  - effect: children ทั้งหมด → cancelled
  - effect: เงินตาม R-07 (credit_ledger / refund pending / forfeited)
  - effect: late → customer.late_cancel_count_12m + 1 แล้ว R-09
