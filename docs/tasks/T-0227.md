## Contract (คัดจาก 05 — ชื่อฟิลด์/ชนิด/บังคับ ต้องตรงทุกตัว)

**`commissionRules.list`** — `GET /api/v1/staff/commission-rules` · สิทธิ์ `staff` roles `O`

Response: `CommissionRuleItem[]` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05

**`commissionRules.set`** — `PUT /api/v1/staff/commission-rules` · สิทธิ์ `staff` roles `O`

Request body:

| field | type | req | maps to | validation |
|---|---|---|---|---|
| `rules[].serviceId` | uuid |  | commission_rule.service_id |  |
| `rules[].staffUserId` | uuid |  | commission_rule.staff_user_id |  |
| `rules[].type` | enum:commission_type | ✓ | commission_rule.type |  |
| `rules[].value` | int | ✓ | commission_rule.value | percent: 0–10000 bps |

Response: `CommissionRuleItem[]` — ดูฟิลด์ DTO ที่ anchor `dto-<Name>` ใน 05
Audit: `commission_rule.update`
ผลที่ต้องเกิด:
- แทนที่ทั้งชุด; ไม่กระทบ commission_entry เดิม

## Test cases ที่ต้องมี (integration, PGlite)

**commissionRules.list** (GET `/api/v1/staff/commission-rules`)
  - happy path: response ตรง schema `CommissionRulesListResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role front_desk/staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
**commissionRules.set** (PUT `/api/v1/staff/commission-rules`)
  - happy path: response ตรง schema `CommissionRulesSetResponse` และค่าที่บันทึกใน DB ตรงกับ 'maps to' ของแต่ละฟิลด์
  - ฟิลด์บังคับขาด/ผิดรูปแบบ → `VALIDATION_FAILED`
  - role front_desk/staff → `FORBIDDEN`
  - ข้อมูลของ organization อื่น → `NOT_FOUND`
  - audit_log action `commission_rule.update` ถูกเขียนใน transaction เดียวกัน
  - effect: แทนที่ทั้งชุด; ไม่กระทบ commission_entry เดิม
